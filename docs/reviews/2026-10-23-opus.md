## Evidence from live probes (keyless default stack)

| Query | What came back |
|---|---|
| `coffee`, `fastapi`, `python asyncio gather exceptions`, `site:github.com fastapi` | Organic results look Google-quality and Google-ordered. `site:` works. One link carries `?srsltid=...`, Google's Merchant Center click-tracking parameter, which only shows up on links taken from Google SERPs |
| `einstein` | No knowledge graph. Wikipedia's KG only fires when the article title equals the query exactly (`_same_entity`). Same for `engine=wikipedia&q=einstein` |
| `what is the capital of australia`, `weather vienna` | No `answer_box`. DDG IA returned nothing useful. Organic results were fine |
| `coffee near Austin, Texas` | 10 OSM cafes with addresses, some with hours. No ratings, reviews or price. The organic results are listicles |
| `asdkjqwlekjzxcmnqwe` (gibberish) | 10 irrelevant results ("USAspending.gov", a garbled PDF title) with `organic_results_state: "Results for exact spelling"`. No "Fully empty" |
| `safe=active` (`q=sex`) | Ignored silently, since the Firecrawl/Wikipedia/DDG paths have no safe-search mapping |
| `tbs=qdr:d` (news query) | Ignored silently. `date` is null on every Firecrawl result, so freshness is invisible |
| `engine=google_news` | 400 "Unsupported". Images, news, scholar, shopping, jobs, autocomplete: none exist |
| 6 concurrent `pizza in <city>` | Latencies 1.7, 2.0, 3.1, 4.6, 5.1, 6.2 s. The Nominatim 1 req/s lock serializes the whole response, organic results included |
| Pagination links | `http://localhost:8000/...` while the server ran on :8791. `FAIRSERP_PUBLIC_URL` defaults silently to a wrong value |

Firecrawl's own code: `apps/api/src/search/index.ts` routes hosted search through the closed "fire-engine" (Google-style `tbs`/`lang`/`country` params). With no fire-engine it falls back to SearXNG, and then to `ddgSearch`, which **scrapes `html.duckduckgo.com/html`**. RESEARCH.md itself calls that path robots-disallowed and found it challenge-protected.

## Must fix before going public

### 1. The default "legal" organic source is very likely Google results via an undisclosed intermediary. Say so, or change the default. (S to M)
**What.** `engine=google` with no keys answers from Firecrawl Keyless. The README and `/engines` label it **"Official API"** and frame the whole project as "official and openly licensed sources only". The live results carry Google's `srsltid` tracking parameter and match Google's ordering. Firecrawl documents no index provenance ("a curated index"). Its open-source fallback scrapes DuckDuckGo HTML.

**Why it matters.** The project's whole pitch, and its moat against openserp and the other scrapers, is legal cleanliness. Your own RESEARCH.md says *Reddit v. SerpApi* let a § 1201 claim reach **Perplexity, the paying customer**. A project whose default path is "Google SERP data laundered through a third party" has the same structure, one hop removed. "We call an official API" is a contract position, not a provenance position. A sophisticated adopter (or a critic on HN) will find `srsltid` in five minutes, and the "fair" brand dies on contact.

**Sketch.**
- Add a `provenance` field per engine, separate from `compliance`: `own-index` (Brave, Mojeek, Marginalia, Wikipedia, OSM), `undisclosed` (Firecrawl, Tavily, Exa until they publish their sources), `user-operated` (SearXNG).
- Put it in `/engines`, in the README table and in `fairserp_sources`.
- Make the zero-key default honest. Either (a) keep Firecrawl but label it "undisclosed upstream, may include third-party SERP data", or (b) default `organic_priority` to own-index sources and require an explicit `FAIRSERP_ALLOW_UNDISCLOSED_PROVENANCE=true` to use Firecrawl/Tavily.
- Add a RESEARCH.md paragraph on intermediary risk.
- Ask Firecrawl directly what backs hosted search and record the answer.

### 2. The paid adapters have never touched their real APIs. (S, needs keys)
**What.** `tests/fixtures/README.md` says the Brave, Mojeek, Tavily and SearXNG fixtures were "written by hand from each provider's published response schema". These are the adapters the README recommends for "stronger organic results". The parser tests only prove that the parser agrees with the author's reading of the docs.

There is already one real bug a recorded fixture would have caught. Tavily's `fetch` sends `country` only when `len(request.gl) > 2`, but `gl` is validated to exactly two letters, so the branch is dead and `gl` never reaches Tavily (Tavily wants a full country name). Firecrawl gets `country`, which its v2 search docs don't list. Meanwhile `tbs`, which it does support, is never forwarded.

**Why.** Shipping untested integrations under a "works after a base-URL change" promise is how an OSS project gets its first ten issues, all titled "brave returns 502".

**Sketch.**
- Get trial keys (Brave $5 credit, Tavily free tier, Mojeek trial) and run `scripts/record_fixtures.py` against each.
- Add a nightly CI job, keyed by repo secrets, that sends one live query per configured engine and diffs the result *shape* against the fixtures, so schema drift turns CI red instead of reaching users.
- Map `gl` to Tavily's country names, forward `tbs` to Firecrawl, and drop `country` for Firecrawl unless its docs confirm the parameter.

### 3. Silent degradation: `engine=google` returns 200 with whatever survived. (S)
**What.** `CompositeEngine._organic` takes the first engine that doesn't raise. Three consequences:
- An engine that returns **zero or garbage results** counts as success. The gibberish probe got 10 junk results labeled "Results for exact spelling".
- When Firecrawl's per-IP daily cap runs out, the chain falls to Marginalia's shared `public` key, which RESEARCH.md says is usually exhausted, and then to `wikipedia`. So `engine=google` quietly becomes Wikipedia search with HTTP 200.
- `safe`, `tbs`, `hl` and `gl` are dropped silently by engines that don't support them.

**Why.** SerpApi clients never read `fairserp_sources`. A LangChain agent or a dashboard will consume Wikipedia hits as "Google results" and nobody will notice. That is worse than failing.

**Sketch.**
- Add `search_information.fairserp_degraded: true` plus a `fairserp_ignored_params: ["safe", "tbs"]` list. Each engine declares `supported_params`, and the composite computes the difference.
- Add `FAIRSERP_STRICT=true`, which turns ignored `safe=active` into a 400. Safe search silently off is a child-safety bug for consumer apps.
- Treat "0 organic results" as a soft failure that tries the next engine.
- Remove `wikipedia` from the default organic priority. It is an enrichment source.

### 4. Quotas can be evicted, and nothing protects the shared upstream budget. (S to M)
**What.**
- Compose runs Redis with `maxmemory 256mb` and `volatile-lru`. Usage counters have TTLs, so they are eviction candidates. Once the 31-day archive of full responses (roughly 10 to 30 KB each) fills 256 MB, Redis starts evicting `usage:hour:*` keys, which resets hourly quotas.
- `MemoryStore` drops "oldest entries" when it holds 50k items, and that can include usage counters.
- There is no per-key monthly cap and no **global** upstream budget. Firecrawl Keyless has one per-IP daily cap per server, so a single tenant's 1,000 searches an hour drains it for every key on the box.

**Why.** Quotas and multi-tenancy are a headline gap fairserp claims to fill (RESEARCH.md §2, "API keys, hourly quotas..."). Right now they are best-effort.

**Sketch.**
- Store counters and the archive in separate logical DBs or key spaces. Use `noeviction` for counters, or make counters persistent with explicit `EXPIREAT` and put the archive under its own memory cap.
- Archive by reference: store `{owner, cache_key}` instead of a full copy when the response is already cached.
- Add `FAIRSERP_UPSTREAM_BUDGETS=firecrawl:500/day,brave:2000/month`, decremented per upstream call. Skip an engine in the composite when its budget is spent and surface that in `fairserp_sources`.
- Add `key:hourly:monthly` limits to `FAIRSERP_API_KEYS`.

### 5. The Nominatim politeness lock holds the whole search response hostage. (S)
**What.** `HttpPool._respect_host_interval` serializes Nominatim calls behind an in-process `asyncio.Lock`. Queue wait is outside the httpx timeout, and `CompositeEngine.search` awaits all enrichers before returning. Measured: 6 concurrent local queries took up to 6.2 s, so 100 would take about 100 s, with no upper bound. With several replicas each one keeps its own spacing, so the public instance sees N req/s, which breaks the OSM policy the code claims to enforce.

**Sketch.**
- Give enrichers a deadline. Use `asyncio.wait_for(enricher, timeout=organic_latency + 300ms)`, or return organic results as soon as they arrive and drop late enrichers with `status: "timeout"`.
- Replace the lock with a token bucket in the Store (Redis `SET NX PX 1000` per host), so spacing holds across replicas. If the next free slot is more than about 1.5 s away, skip and say so instead of queuing.
- Cache Nominatim results per normalized `(phrase, place)`. The current cache key is the whole SerpApi request.

### 6. Proxy rotation contradicts the project's own legal line. (S)
**What.** `FAIRSERP_PROXIES` is "rotated round robin" across requests. The README says rotation is for "egress control" and that fairserp "never rotates to another proxy to retry". But per-request round robin over a pool *is* IP rotation, and the only engine where an IP matters is Firecrawl Keyless, whose limit is a **per-IP daily cap**. Spreading keyless calls over N egress IPs evades that cap by construction. "Running across many IPs" is one of the methods in Google's complaint that the court held adequately alleged as circumvention.

**Sketch.**
- Remove round robin. Allow one proxy per engine (sticky), which covers the corporate-egress and residency use cases.
- Refuse to start if more than one proxy is configured for a keyless engine.
- Document the reason in RESEARCH.md §4.

### 7. Smaller correctness and security fixes, one PR. (S)
- **Pagination lies past the upstream window.** Firecrawl's `limit` is capped at 100 and Tavily's `max_results` at 20, but `has_next = count >= num`. On Tavily, page 3 is advertised and then returns "Fully empty". Cap `next` at the engine's real `max_depth`.
- **`FAIRSERP_PUBLIC_URL` silently wrong.** On a non-default port, every `next`/`json_endpoint` link points to `localhost:8000`, which breaks `results.next_page()` in the official client. Derive it from `request.base_url` when unset (proxy headers are already trusted), and log a warning at boot.
- **Stuck async jobs.** `async=true` is an in-process `asyncio.Task`. A restart or OOM leaves `status: "Processing"` in the archive for 31 days. Write the stub with a short TTL, and on read mark Processing older than `http_timeout*3` as Error. If async matters, use a Redis list worker.
- **Privacy.** `zero_trace` still writes `q` to the uvicorn access log. Redact `q` when `zero_trace=true`, or add `FAIRSERP_LOG_QUERIES=false`.
- **Key leak risk.** Mojeek's key travels as a query param. If anyone enables `httpx` INFO logging, it ends up in logs. Add a redaction filter on the `httpx` logger too.
- **Stored XSS vector.** `output=html` escapes but doesn't check the URL scheme. A `javascript:` link from a user-operated SearXNG upstream becomes clickable on the fairserp origin. Allow only `http`/`https` in `render.to_html`.
- **`/engines` is unauthenticated.** It discloses which paid upstreams are configured and the priority order. That's minor, but put it behind auth or trim it.
- **`/healthz` doesn't check Redis.** Compose's `--wait` passes while every search would 500. Add `/readyz` that pings the store.
- **The Wikipedia KG is too strict.** It needs the exact title (`einstein` gets no KG). Use the Wikidata/REST summary of the top hit when its score is high and `hits[0].title` contains every query token. Better still, use `wbsearchentities`.

## Makes it amazing

### 8. Reposition: an agent-first, provenance-first search layer that also speaks SerpApi. (M)
**Who actually hires a SERP API, and does fairserp do the job?**

| User | Job | Does fairserp do it? |
|---|---|---|
| SEO rank trackers (SerpBear etc.) | "Where does *my site* rank **on Google** for X in city Y" | **No, and it can't.** Positions from Firecrawl/Brave/Mojeek aren't Google ranks. Pointing SerpBear at fairserp produces confident wrong data. Say this explicitly in the README |
| LangChain `SerpAPIWrapper` legacy users | "Give my agent a few relevant snippets" | Yes, but this cohort is shrinking. New agent code uses Tavily/Exa/Brave/Parallel tools or MCP, not SerpApi JSON |
| AI agent builders (the growth market) | Relevant URLs, **clean extracted text**, freshness, citations, low latency, cheap, works in Claude/Cursor | Partly. Fine URLs, poor snippets (Firecrawl's `description` is page lead text, not query-biased), no content fetch, no MCP |
| Privacy self-hosters | A private metasearch UI | No. SearXNG owns this, and fairserp has no UI |
| Researchers / data teams | Reproducible, licensed, citable result sets | **Yes, uniquely, if provenance is real.** Nobody else offers per-result license and source |

The SerpApi wire format is a good **adapter**, not a good **identity**. "Drop-in SerpApi replacement" invites comparison on Google fidelity, which fairserp loses by design: no ads, no AI overview, no top stories, no shopping, and it isn't Google. The defensible identity is **"the open, self-hosted search gateway for agents, with license-clean provenance on every result"**. That means:
- one normalized result schema with `provenance: {engine, index_owner, license, cache_policy, retrieved_at}` on **every result**, not just in metadata;
- multiple wire dialects as thin shims: SerpApi (keep it), plus **Tavily-compatible `/search`**, **Brave-compatible** and **OpenAI/Anthropic tool-call shapes**, because agent code is written against those now;
- an MCP server as the primary distribution channel (item 9).

Keep the name question open (item 14).

### 9. Ship an MCP server and a fetch/extract tool. (M)
**Why.** In 2026 the main way a developer meets a search tool is "add this MCP to Claude/Cursor". Parallel, Exa, Firecrawl and Tavily all ship hosted MCP servers that work **keyless** (Exa `mcp.exa.ai`, Parallel `search.parallel.ai/mcp`, Tavily with `X-Tavily-Access-Mode: keyless`, Firecrawl per-IP). Every one exposes **search plus fetch**, because agents need page text, not 160-char snippets. fairserp has neither.

**Sketch.**
- `fairserp mcp` (stdio) plus `/mcp` (streamable HTTP) with tools `web_search(q, num, freshness, site, country)`, `local_search(q, near)`, `entity(q)` (KG) and `fetch(url)`.
- `fetch` = httpx GET plus robots.txt check plus readability/trafilatura to markdown, with a size cap. Respect robots and don't evade blocks (same legal line). Reject private IPs (see the SSRF note in item 15).
- Publish to the MCP registry and give a one-line `claude mcp add` install command.

### 10. Real result quality: fuse, don't fall back. (M to L)
**What.** Today exactly one organic engine answers, and enrichment only fills gaps. That throws away the one structural advantage a gateway has over a single provider: **several independent indexes**.

**Sketch.**
- **Fan-out with budget.** Query the top 2 or 3 configured organic engines in parallel with a latency deadline, for example Brave plus Mojeek plus Marginalia (three independent indexes), or Firecrawl plus Wikipedia.
- **Reciprocal Rank Fusion** (`score = Σ 1/(60 + rank)`) over URLs normalized by lowercasing the host, stripping `utm_*`/`srsltid`/`fbclid`/`ref` and trailing slashes, and collapsing `m.`/`www.`. RRF is parameter-light and robust, and it's what SearXNG and most metasearch engines do in spirit.
- **Dedup by canonical URL plus near-duplicate title.** Keep the best snippet and record every contributing engine in `result.sources[]`, which doubles as provenance.
- **Query-biased snippets.** If the upstream snippet doesn't contain the query terms, take the best 1 or 2 sentences from the page (needs `fetch`, so make it optional and cached).
- **Freshness.** Map `tbs=qdr:h/d/w/m/y` to each engine (Brave `freshness`, Firecrawl `tbs`, Tavily `time_range`, SearXNG `time_range`) and fill `date` everywhere.
- **Answer box.** Add Wikidata for factoid questions (`capital of X`, `population of X`, `height of X`) with simple property templates, plus a tiny calculator and unit converter. DDG IA alone gives near-zero coverage, as the live probes showed.
- **KG.** Look up `wbsearchentities` on Wikidata and use its claims (born, died, founded, HQ, CEO) for SerpApi-style KG attributes. That is far richer than the summary extract, which is currently dumped untruncated as `description`.
- **Local.** Swap Nominatim free-text for **Overpass or a self-hosted Photon** with category tags, sort by distance from the geocoded `location`, and add `opening_hours` parsing into `hours` plus `open_now`. Be honest in docs that there are no ratings or reviews.

### 11. Publish a benchmark, because that's the adoption lever. (M)
**Why.** "How good is it?" is the first question, and right now there is no answer except vibes. Agent-search vendors compete on public evals (SimpleQA-style, BrowseComp, the Artificial Analysis search index).

**Sketch.**
- `bench/` with three tracks:
  1. **Agent QA:** 200 SimpleQA-style questions, with search plus a fixed small LLM, scoring answer accuracy.
  2. **Navigational:** 200 "official site of X" queries, scoring whether the right domain is in the top 3.
  3. **Overlap with Google:** a small, manually collected Google top-10 set (collected by a human, not scraped), scoring nDCG@10 per engine config.
- Report it per engine and per fused config, with $/1k and p50/p95 latency.
- Put the table in the README and regenerate it monthly in CI with secrets.

### 12. A 60-second quickstart that doesn't need Docker, and a playground. (S to M)
- `uvx fairserp` (publish to PyPI; `fairserp` is free there) with `FAIRSERP_AUTH_DISABLED` defaulting to true **only when bound to 127.0.0.1**. That removes the "set an API key for localhost" friction without opening a relay.
- A `/` page: a search box, a JSON viewer, a per-engine provenance badge and a "copy as curl / Python / LangChain / MCP config" button. One static HTML file, no build step.
- Publish a GHCR image so `docker run ghcr.io/.../fairserp` works without `build:` and a 3-minute local build.
- Write a docs site (mkdocs-material) with one page per engine: what it costs, how to get a key, what params map, and its legal notes.

### 13. A plugin/adapter API that outsiders can actually extend. (S to M)
**What.** Adding an engine today means editing `engines/__init__.py`. The `Engine` contract is clean (pure `parse`, which is good). Open it up:
- Entry points (`fairserp.engines`), so `pip install fairserp-exa` registers itself.
- Engines declare `supported_params`, `max_depth`, `provenance`, `cost_per_call` and `rate_limit`. That feeds items 3, 4 and 10 from data instead of special cases.
- Use an adapter cookiecutter, and make `record_fixtures.py` part of the contract: CI fails if an engine has no recorded (not handwritten) fixture.
- Next adapters by value: **Exa** and **Parallel** (keyless/free, agent-grade), **Tavily keyless**, **Jina `s.jina.ai`** (search plus reader), **Yandex** (official, the only non-US index), **Kagi**, **You.com**. Also add **Wikidata** and **Overpass/Photon** as enrichers.

### 14. License and name: decide on purpose. (S)
- **License.** AGPL protects against a closed hosted fork, but this project's value is being *embedded*: agent frameworks, internal tools, MCP configs. Many company policies auto-reject AGPL dependencies even for internal use, and the realistic "threat" (someone hosting a paid fairserp) is small next to the adoption cost. Recommendation: **Apache-2.0** for the core and SDK/MCP, which also gives a patent grant. If you want hosting protection, keep a trademark policy on the name rather than copyleft. If you stay AGPL, say plainly in the README that calling the HTTP API from proprietary code is fine (it is), because that is the FAQ that blocks adoption.
- **Name.** "fairserp" says "SERP" (Google results page, which it is not) and "fair" (a claim item 1 currently undercuts). The repo directory is `open-serp` and the remote is `fairserp`, so pick one. If you reposition per item 8, a name around provenance, open or agents travels better. `openserp` is taken on PyPI and is also karust's scraper, so avoid it.

### 15. Contributor and governance basics, plus a security policy. (S)
- `CONTRIBUTING.md` with the adapter recipe and the legal line ("PRs adding HTML scrapers, challenge solving or IP rotation will be closed"). That line *is* the governance.
- `SECURITY.md`, a CODEOWNERS file, issue templates (engine request, engine broken with `/engines` output), and Dependabot.
- Before the `fetch` tool ships, an **SSRF guard**: resolve and reject private, loopback and link-local addresses, cap redirects at 3 and re-check each hop, and cap size and time. Today SSRF is low because every upstream URL is operator config (`searxng_url`, `nominatim_url`, `firecrawl_url`) and `hl` is validated before it becomes a Wikipedia subdomain. `fetch(url)` changes that completely.
- A tests gap worth closing: there are no tests for Redis (`RedisStore` is untested), no concurrency tests, and no test that a real SerpApi client's `next_page()` works with a non-default `PUBLIC_URL`. Add a `fakeredis` or testcontainers path to CI.

## Verdict

The engineering is tidy and the SerpApi wire emulation is careful: error semantics, archive, cache-is-free, the official-client compat check in CI. But the product is shaped like SerpApi without doing SerpApi's job. It cannot give rank trackers Google positions. For agent builders it offers less than the keyless Tavily, Exa, Parallel and Firecrawl MCP servers they can already add in one line. And its central promise, "legal sources only", currently rests on a default upstream whose results carry Google's own tracking parameters, behind a label that says "Official API".

Fix the provenance story first. It is the only thing here no competitor can copy cheaply, and today it is the weakest claim. Then stop falling back and start fusing several independent indexes, ship an MCP server with fetch, and publish a benchmark. Do that, and fairserp becomes a credible open "agent search gateway with license-clean provenance" that also happens to speak SerpApi. Without it, this is a well-built adapter for a shrinking LangChain-era API shape.

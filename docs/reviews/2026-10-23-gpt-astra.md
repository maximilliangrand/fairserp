fairserp currently delivers **a partial SerpApi-shaped adapter, with unproven search quality and several broken operational guarantees**. Its strongest potential audience is teams building agents who need control over providers, cost, privacy, and evidence.

I read the application, adapters, tests, fixtures, research, deployment files, and CI. All **58 tests and lint pass**. Additional in-memory checks reproduced failures described below. No files were edited. I did not run Docker or a live, paired Google/SerpApi relevance benchmark.

The customer distinction matters:

| Audience | Job they need done | Current fit |
|---|---|---|
| AI agent builders | Find relevant, current, attributable evidence within a latency/cost budget | Plausible audience; little differentiation yet |
| LangChain users | Replace a tool without changing its behavior or leaking requests | Partial compatibility; async integration is broken |
| SEO rank trackers | Observe actual Google rankings for a location, device, and time | Fundamentally unsuitable |
| Privacy self-hosters | Control who sees queries and what gets retained | Gateway is local; queries still reach multiple external providers |
| Researchers | Reproduce searches and inspect provenance, coverage, and bias | Missing snapshots, detailed provenance, and evaluation |

Effort: **S** = focused change; **M** = substantial feature; **L** = architectural or ongoing work. Ranked within each release tier.

**Must fix before going public**

1. **Replace the misleading product promise. — M**

   **Why:** Google rank tracking requires observing Google. Returning Firecrawl, Marginalia, or Wikipedia under `engine=google` changes the meaning of the result. A provenance field does not restore that meaning. “Missing blocks are normal in SerpApi” also does not justify permanently missing capabilities.

   **Implementation:** Position this as **“self-hosted search infrastructure for agents, with a SerpApi compatibility endpoint.”** Make Google/Bing aliases an explicit migration setting. Publish a capability matrix covering parameters, verticals, pagination, and response semantics. Distinguish requested engine, actual provider, applied parameters, and ignored parameters. Remove SerpBear/rank-tracking implications unless a genuine, authorized source of those rankings exists.

2. **Turn “legal-first” into enforceable provider policies. — L**

   **Why:** “Official API” describes an interface, not permission for every downstream use. Brave’s current standard terms restrict redistribution, replacement functionality, storage, and certain AI evaluation uses; order forms can change the applicable rights. Marginalia’s free keys carry noncommercial conditions. These directly affect the proposed product. [Brave terms](https://api-dashboard.search.brave.com/terms-of-service), [Marginalia API terms](https://about.marginalia-search.com/article/api/).

   **Implementation:** Replace the three-value compliance label with deployment-specific rights: commercial use, redistribution, enrichment, storage, evaluation, attribution, and applicable agreement/version. Keep unverified providers out of a strict profile. Require explicit configuration for noncommercial sources and user-operated SearXNG. Firecrawl’s public implementation contains multiple upstream paths; that does **not** establish the hosted service’s acquisition rights. Verify those separately before making blanket claims. [Firecrawl source](https://raw.githubusercontent.com/firecrawl/firecrawl/main/apps/api/src/search/index.ts).

3. **Fix retention across caches, archives, and enrichment. — M**

   **Why:** The archive defeats the cache policy. I reproduced approximately **one hour of Brave archival storage despite cache TTL zero**, and **31 days for Mojeek despite its declared one-hour cap**. Calling a copy an “archive” does not exempt it from storage terms. Mojeek explicitly distinguishes one-hour caching from plans granting storage rights. [Archive code](fairserp/app.py:204), [Mojeek terms summary](https://www.mojeek.com/services/search/web-search-api/).

   **Implementation:** Give every fragment an absolute retention deadline and enforce it across archive copies, cache hits, async results, and persistence. Cache upstream fragments independently: Brave disabling the assembled cache currently also prevents reuse of Nominatim enrichment. Carry attribution through JSON, Markdown, and HTML. Coordinate Nominatim limits across workers; a process-local lock is insufficient. Public Nominatim also has restrictions beyond one request per second, including geocoding resale. [Nominatim policy](https://operations.osmfoundation.org/policies/nominatim/).

4. **Separate enforceable quotas from disposable cache storage. — M**

   **Why:** I reproduced cache pressure deleting a quota counter. The memory backend evicts entries without distinguishing accounting from cache; Compose’s Redis `volatile-lru` policy likewise makes expiring accounting records eligible for eviction. Free cache hits create fresh archive entries, so they can generate storage pressure without consuming search quota. [Storage](fairserp/store.py:77).

   **Implementation:** Put accounting in non-evicting storage and make reservation/settlement atomic and idempotent. Return a reservation token containing the original hour bucket: `_release_quota()` currently recalculates the hour, and I reproduced a cross-hour failure refunding another request’s bucket. Add independent request-rate, concurrency, archive-write, and provider-spend limits. Failed searches may be free financially; they cannot be unlimited computationally.

5. **Audit actual client behavior and parameter semantics. — M**

   **Why:** The documented LangChain patch does not affect async requests: current `aresults()` hardcodes `https://serpapi.com/search`. That can send the user’s fairserp credential and query to SerpApi. [LangChain implementation](https://raw.githubusercontent.com/langchain-ai/langchain-community/master/libs/community/langchain_community/utilities/serpapi.py).

   Pagination is also guessed from result count. Brave offsets are clamped, potentially repeating pages; Tavily stops at 20 results; Firecrawl stops at 100. Tavily’s country mapping is unreachable because it requires `len(gl) > 2` after validation requires two letters. Several adapters ignore requested safety, language, or location constraints.

   **Implementation:** Test sync/async Python, legacy Python, both Node clients, and LangChain separately. Provide an explicit async adapter immediately. Use provider capabilities and continuation metadata; reject unsupported constraints or report them prominently. Never silently relax a safety filter during fallback.

6. **Distinguish provider failure, legitimate emptiness, and degraded results. — M**

   **Why:** I supplied Firecrawl’s parser an HTTP-200 failure envelope: it became a billed `Success`, with no fallback. `_organic()` accepts the first non-throwing response even if it contains no organic results. SearXNG’s `unresponsive_engines` is discarded. Malformed location data produced a plain-text 500. Invalid `json_restrictor` was rejected only after performing and billing the search. [Fallback](fairserp/engines/composite.py:70), [Locations](fairserp/locations.py:15).

   **Implementation:** Validate request formatting before upstream work. Validate provider envelopes and classify outcomes as success, empty, partial, refused, rate-limited, or failed. Define when empty results should trigger fallback. Normalize storage and parsing errors into the documented error envelope. Legitimately empty searches can remain billable for SerpApi compatibility; upstream failures must not masquerade as emptiness. [SerpApi semantics](https://serpapi.com/api-status-and-error-codes).

7. **Close credential, rendering, and egress gaps. — M**

   **Why:** The log filter misses encoded parameter names such as `api%5fkey`; I reproduced the credential remaining visible. It only filters Uvicorn access logs. HTML escaping also leaves `javascript:` result URLs executable when clicked. [Logging](fairserp/app.py:29), [Rendering](fairserp/render.py:25).

   **Implementation:** Prefer bearer authentication; log structured, sanitized fields instead of raw query strings; redact outbound URLs and secret-bearing configuration errors. Allow only HTTP(S) result links and add a restrictive CSP. Validate configured upstream/proxy destinations and require explicit private-network allowances for self-hosted services. **I did not find a caller-controlled arbitrary-URL SSRF endpoint**: these URLs are administrator settings, so describe that trust boundary accurately. Set HTTPX environment-proxy behavior explicitly; currently `"none"` does not necessarily mean direct egress. Explain that `zero_trace` does not control upstream retention.

8. **Make async work durable and put deadlines around the whole search. — L**

   **Why:** `asyncio.create_task()` is not a durable job system. A restart can leave an archived `Processing` response without a worker capable of completing it. Redis shares records, not execution. Sequential fallback can accumulate multiple timeouts, while optional enrichment delays otherwise usable organic results. [Async submission](fairserp/app.py:257).

   **Implementation:** Either remove the durability implication or introduce persisted jobs with leases, bounded queues, expiration, recovery, and exactly-once quota settlement. Add overall request deadlines, smaller enrichment budgets, provider concurrency limits, and circuit breakers respecting `Retry-After`. Cancel remaining tasks cleanly. Add readiness checks for required storage and metrics for provider failures, queue age, latency, cost, and degraded responses.

9. **Replace reassuring coverage with adversarial contract tests. — M**

   **Why:** Passing tests currently coexist with all the reproduced failures above. Brave, Mojeek, Tavily, and SearXNG fixtures are handwritten, as the fixture README acknowledges. CI’s live queries establish that something responds; they do not establish adapter fidelity. The compatibility script prints several outcomes without strong assertions. [Fixture disclosure](tests/fixtures/README.md:8), [Compatibility script](scripts/compat_check.py:12).

   **Implementation:** Add request-contract tests for every adapter, permitted recorded responses with provenance, and negative payloads. Test Redis behavior, eviction pressure, concurrent reservations, hour boundaries, restart recovery, retention, and pagination uniqueness. Assert actual destinations in client integration tests. Keep deterministic integration tests in required CI; run external-provider canaries separately so upstream outages do not randomly block unrelated contributions.

**Makes it amazing**

10. **Publish a benchmark that measures the customer’s job. — M**

    **Why:** There is no defensible numerical answer to “how good versus Google?” today. The current adapter largely inherits the first provider’s ranking and discards information. Coffee and Einstein fixtures cannot establish relevance, freshness, or coverage.

    **Implementation:** Build a stratified query set covering technical troubleshooting, navigation, ambiguous entities, current events, multilingual queries, and local intent. Compare fairserp with each contributing provider directly and a lawfully obtained Google/SerpApi baseline where permitted. Measure relevance, answer-supporting evidence, duplicate rate, freshness, latency percentiles, and cost per successful task. Use blinded judgments and holdout queries. Respect evaluation/storage restrictions; publish aggregate results where raw-result redistribution is prohibited.

11. **Build routing and fusion that demonstrably outperform a single adapter. — L**

    **Why:** The current “composite” is sequential failover plus enrichment. It performs no organic fusion, reranking, or deduplication. More providers alone create more expense and more disclosure of queries.

    **Implementation:** Offer explicit policies such as `fast`, `research`, and `private`. Route by supported language, freshness, domain, and task requirements. In research mode, query a small, policy-approved set concurrently; canonicalize URLs conservatively, remove tracking parameters, deduplicate, and apply reciprocal-rank fusion before considering a reranker. Preserve each provider’s original rank. Do not treat two providers sharing an underlying index as independent corroboration. Ship fusion only when the benchmark shows a benefit relative to its cost.

12. **Make evidence quality the differentiator. — L**

    **Why:** Flattening and truncating snippets to 300 characters is presentation cleanup, not relevance improvement. The Firecrawl fixture begins with Wikipedia disambiguation boilerplate. Wikipedia edit dates are presented as generic result dates. Tavily’s generated answer is labeled `organic_result`. Local “pizza” becomes generic “restaurant,” and entity enrichment relies on fragile matching.

    **Implementation:** Preserve query-relevant passages, citation URLs, provider, retrieval time, and distinct publication/update timestamps. Label generated answers explicitly and retain supporting citations. Add Wikidata identifiers, entity-confidence thresholds, and revision provenance. For local discovery, use geographic bounds, distance, category/cuisine filters, and licensed or self-hosted POI data. Preserve unknown ratings and opening status as unknown. Keep source attribution attached to every block.

13. **Make the first useful integration take one minute. — L**

    **Why:** Host monkey-patching and custom HTTPS agents are poor onboarding. FastAPI currently exposes no search parameters in OpenAPI because the handler reads the raw request. There is no native SDK, MCP server, or meaningful interactive playground.

    **Implementation:** Add a typed native API, thin Python/TypeScript clients with explicit `base_url`, and an MCP search tool returning compact cited evidence. Provide a tested LangChain integration. Publish versioned container images and a copy-paste quickstart with readiness checks, provider diagnostics, and a localhost binding. Include an explicitly labeled offline example mode and a capped hosted playground funded under suitable provider terms. Show actual provider, latency, and estimated cost in every demo.

14. **Make federation extensible; pursue a narrow index only where it wins. — L**

    **Why:** Building a general-web index would multiply the project’s hardest problems. A more defensible advantage is combining permitted public search with a user’s own authoritative corpus.

    **Implementation:** Evolve the adapter contract into typed capabilities, rights, request planning, results, continuations, usage, and health. Support externally installed adapters through entry points and a conformance suite. Add federation with user-owned documentation or explicitly licensed datasets, enforcing document permissions before ranking and caching. Start with a narrow benchmarkable use case—such as company documentation plus public technical references. Under the no-scraping constraint, source any owned index from authorized documents, feeds, or licensed dumps.

15. **Choose adoption and governance deliberately. — M**

    **Why:** AGPL does not prevent competitors from hosting the software commercially; its network provision concerns modified versions and corresponding source. The research overstates its protection against hosted competition. For an integration layer, adoption friction may cost more than closed forks.

    **Implementation:** If broad infrastructure adoption is the priority, prefer **Apache-2.0**, including its explicit patent grant; MIT is simpler but less explicit on patents. Retain AGPL if reciprocal source availability is the actual objective, and explain that tradeoff accurately. [Apache license](https://www.apache.org/licenses/LICENSE-2.0.html). Add contribution instructions, maintainer responsibilities, security reporting, release/deprecation policies, and an adapter roadmap. Keep `fairserp` unless naming checks reveal a conflict, but drop any implication that “fair” certifies legal clearance or ranking neutrality.

**Verdict:** Do not launch this as a drop-in SerpApi alternative. It cannot satisfy Google-observation use cases, its legal assurances exceed the evidence, and its passing tests miss broken retention, quota, compatibility, and error guarantees. The strongest product is a self-hosted search layer for agents that makes provider selection, permissions, cost, and evidence inspectable, with SerpApi compatibility as a migration feature. Without measured retrieval improvements and operational trustworthiness, it is another wrapper around APIs users can already call directly.
